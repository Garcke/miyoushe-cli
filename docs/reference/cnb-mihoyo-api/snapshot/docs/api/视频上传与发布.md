# 视频上传与发布流程(实测,2026-09-03)

> 来源:App 实测抓包(图文+视频混合帖发布全流程,星布谷地社区 gids=10)
> 结论:**图文/长文的 `releasePost/v2` 支持视频附件**——视频以 Quill delta 嵌入块混排在正文中,与图片/文本同级。

## 一、视频上传链(全 200 实测)

```
1. GET /post/api/check/publishVideoPerm          # 发布视频权限检查
2. GET /video/api/residualTimes                  # 上传配额(剩余次数)
3. GET /video/api/getToken                       # 取上传凭证(火山引擎 VOD)
     ?size={字节数}&duration={毫秒}&name={文件名}&md5={文件md5}&video_provider=1
4. [火山引擎 VOD 直传]                            # file_id 形如 v0dc41g10002dac525
5. GET /video/api/isExist?md5={md5}&scene=0&video_provider=1     # 秒传检查
6. GET /video/api/getVideoID?file_id={file_id}&md5={md5}&video_provider=1   # 登记得 video_id
7. POST /video/api/updateCover                    # 传封面(body ~165B)
```

- 视频后端为**火山引擎 VOD**:播放经 `prod-vod-sign.miyoushe.com` 防盗链签名 URL;上传由 App 内 VOD SDK 直传火山(不经 bbs-api)。
- 图片上传仍是老链路:`apihub/sapi/getUploadParams?md5=&ext=&support_content_type=1&upload_source=1` → 阿里云 OSS 直传。

## 二、发布:视频作为正文嵌入块

`POST /post/api/releasePost/v2`(草稿为 `/post/api/draft/save`,键略异:draft 用 `forum_id`,release 用 `f_forum_id`+`draft_id`):

- `structured_content` 为 **Quill delta** 数组,三种块混排:
  ```json
  [{"insert": "\n"},
   {"insert": {"vod":   {"cover": "<oss封面url>", "duration": 52208, "id": "<video_id>"}}},
   {"insert": {"image": "https://upload-bbs.miyoushe.com/upload/..."}},
   {"insert": "正文文本"},
   {"insert": "_(表情)"}]
  ```
- `content` 字段 = 同内容的 **HTML 渲染**:视频为 `<div class="mhy-vod" data-cover="...">`(带 video id 属性)
- `view_type`:本次视频混排帖 = **1**;纯图文帖 = **2**;`subject` 为标题(视频帖/长文带)
- 草稿比发布多 `link_card_list`,少 `post_id/review_id/meta_content` 等服务端字段

## 三、发布后审核流

- 帖子进入审核:`GET /post/api/review/detail?review_id={id}`(rc=0,返回 post 全文+`is_editable`)
- 撤回/重提:`POST /post/api/review/undo`(body 23B: `{"review_id":"..."}`)

## 四、三类帖子统一走同一套发布/审核/删除(2026-09-03 双帖实测)

同一次会话发了两帖,证据如下:

| view_type | 类型 | 内容块 | gids | review_id |
|---|---|---|---|---|
| 1 | 视频/图文混排 | vod + image + text | 10(星布谷地) | 2378022 |
| 5 | **长文**(纯文本块+标题) | text | 9(因缘精灵) | 2378021 |
| 2 | 纯图文 | describe+imgs(8-30 HAR) | 8 | (未触发审核) |

- **发布**:三类全走同一个 `releasePost/v2`,只差 `view_type` 和正文块构成
- **审核**:全走同一组 `review/detail` + `review/undo`(仅 review_id 不同,detail 响应直接内嵌 post 全文含 view_type);**是否进审核由风控决定**(新号/低等级触发,老号图文未触发)——接口统一,触发与否不统一
- **删除**:`post/api/deletePost`(body `{operate_type, post_id}`)是 post 域唯一删除接口,dex 中无视频/长文专属删除端点 → 三类共用
- **视频文件**:上传后无客户端删除接口(见下),删帖后文件孤儿化

## 五、已上传视频文件的删除

- 客户端**没有**删除已上传视频文件的接口(`video/api/*` 全集只有 getToken/getVideoID/isExist/residualTimes/updateCover/view)
- 实测"删除视频帖"场景:HAR 中只有 `review/undo`(撤回审核帖)+ 页面加载,无视频文件删除调用;火山 VOD 侧文件随帖子删除而孤儿化
- 结论:删内容 = deletePost / review undo;视频文件本身不可单独删

## 四、第三方复现要点

1. 视频直传火山 VOD 需要其 SDK/签名,`getToken` 的凭证即用于此——复现门槛在火山上传协议,不在米游社签名
2. 若只发图文(无视频):跳过 §一,`structured_content` 只用 image/text 块,`content` 用对应 HTML
3. 全流程请求头与 DS:与[接口清单](米游社接口清单_DS闭环验证.md) §4 一致(bbs DS1 + 15 项头)
